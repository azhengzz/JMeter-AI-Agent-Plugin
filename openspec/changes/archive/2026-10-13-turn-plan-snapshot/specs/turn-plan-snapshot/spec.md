# Spec Delta

## Purpose

回合级测试计划快照：每个 agent 回合在内存持有测试树基线，回合终态比对、有变化才落盘回合起点基线，为「准确回退到某一次回合之前」提供磁盘落点；落盘全异步、best-effort，不影响 GUI 与 agent 运行。

## ADDED Requirements

### Requirement: 回合起点基线无条件捕获

每个进入执行的 agent 回合（本地面板发起、IPC CLI 发起、IPC 委派、goal 续跑重发）SHALL 在首次 LLM 调用之前捕获当前测试计划树的内存基线。捕获 SHALL 无门控：无论计划从未保存、已保存但脏、已保存且干净，均一视同仁（磁盘上的关联文件可能在回合中被保存覆写，MUST NOT 被当作基线替代品）。不进入 agent 执行的纯命令回合（如会话内快捷命令）SHALL 不参与快照。GUI 树读取 SHALL 在 EDT 上完成且成本限于树克隆；序列化 SHALL 在克隆副本上于 EDT 之外进行。

#### Scenario: 干净已保存计划的回合也持有基线
- **WHEN** 计划已保存为 .jmx 且树与文件一致，用户发起一个 agent 回合
- **THEN** 该回合仍捕获内存基线（不因「磁盘即基线」跳过）
- **AND** 回合中修改树并触发落盘时，写出的是回合起点状态（而非磁盘文件当时的内容）

#### Scenario: 覆盖全部回合来源
- **WHEN** 回合分别来自本地面板输入、IPC CLI、对端实例委派、goal 跨回合续跑
- **THEN** 四种来源的回合均捕获基线并参与终态比对

#### Scenario: 无 GUI 环境降级为 no-op
- **WHEN** 插件运行在无 GUI 上下文（如纯单测环境无测试计划树）
- **THEN** 基线捕获安全跳过（记日志），不抛异常、不影响回合执行

### Requirement: 回合终态比对与条件落盘

回合到达任一终态——正常完成、用户 Stop 取消、内部异常中止、会话重置取消——时，系统 SHALL 再次采样测试树并与起点基线比对：字节一致则不产生任何文件；不一致则把**回合起点基线**（非终态）写入一份快照文件。变化判定 SHALL 不区分改动来源：回合存活期内用户在 GUI 手动改树同样触发落盘。终态比对 MUST 覆盖上述全部四种终态路径（含 Stop 打断在改树中途的回合——该回合恰是最需要基线的时刻）。

#### Scenario: 改树回合落盘起点基线
- **WHEN** 回合内 agent 工具修改了测试树，回合正常完成
- **THEN** autosave 目录新增恰一份快照文件，内容为回合起点的树状态
- **AND** 文件不随回合终态树状态而变

#### Scenario: 纯聊天回合零文件
- **WHEN** 回合内未调用任何改树工具且用户未手动改树，回合完成
- **THEN** 终态比对判定一致，不产生快照文件

#### Scenario: 改了又改回的净零回合不落盘
- **WHEN** 回合内树被修改后又恢复到与起点字节一致的状态
- **THEN** 不产生快照文件

#### Scenario: 用户 Stop 中途打断仍比对落盘
- **WHEN** 回合改树中途用户点 Stop（回合以取消终态收敛）
- **THEN** 终态比对照常执行，树已变化则落盘回合起点基线

#### Scenario: 用户手改同样计为变化
- **WHEN** 纯聊天回合进行中用户在 GUI 手动修改了树
- **THEN** 终态比对判定不一致，落盘回合起点基线

### Requirement: 快照文件身份与目录

回合快照与 `run_test` 的启动前 autosave SHALL 统一存放于工作空间 `autosave/` 目录。回合快照文件名 SHALL 编码四元身份：落盘时间戳（保证字典序即时间序）、实例标识 instanceId（双实例共享同一 workspace 目录时隔离，防撞名）、回合标识 turnId（使快照可精确对应到会话中的某一次回合）、回合来源标记（local/cli/delegated/republish）。`run_test` 既有 autosave 文件名 SHALL 补入 instanceId（修复双实例同毫秒撞名）。系统 MUST NOT 新增任何配置项或开关。

#### Scenario: 文件名可定位到具体回合
- **WHEN** 用户/agent 事后列举 autosave 目录
- **THEN** 每份回合快照可由文件名读出产生时间、所属实例、turnId 与来源标记
- **AND** 按文件名字典序排列即按时间序排列

#### Scenario: 双实例同毫秒不撞名
- **WHEN** 两个 JMeter 实例（同一安装目录，共享 workspace）近乎同时产生快照
- **THEN** 文件名因 instanceId 不同而不冲突，互不覆盖

#### Scenario: run_test autosave 文件名含实例标识
- **WHEN** 未保存计划上 agent 调 `run_test` 触发既有 autosave
- **THEN** 落盘文件名含本实例 instanceId（该机制其余行为不变）

### Requirement: 异步执行与 best-effort 失败

序列化、比对、写盘 SHALL 在专用异步通道上执行，MUST NOT 阻塞 GUI（EDT 只承担回合两端各一次树克隆）也 MUST NOT 拖慢回合可见完成时刻。异步任务的执行顺序 SHALL 保证起点序列化先于终点比对完成。快照链路任何环节失败（路径不可写、磁盘满、序列化异常等）SHALL 仅记日志后吞掉，回合执行与结果显示 MUST NOT 受任何影响。快照流程 MUST NOT 修改计划的文件关联（不影响后续 Ctrl+S/退出保存的 Save As 语义）与 IPC 实例注册信息。

#### Scenario: 回合完成不被写盘拖慢
- **WHEN** 大计划的回合终态触发快照落盘
- **THEN** 回合完成事件/界面收尾不等写盘结束（写盘异步进行）

#### Scenario: 快照失败仅记日志
- **WHEN** 快照目录不可写导致落盘失败
- **THEN** 记录一条错误日志，回合正常完成，工具结果与聊天显示无异常

#### Scenario: 快照不改变计划的保存语义
- **WHEN** 任意回合产生快照
- **THEN** 计划的文件关联保持快照前的取值，IPC 端口文件中的 jmx 路径不变

### Requirement: 关闭时有界冲刷未落盘快照

JVM 关闭时，系统 SHALL 对快照异步通道中未完成的任务做有界等待排空（默认量级约 2 秒），超窗未完成的任务放弃（best-effort 一以贯之）。

#### Scenario: 干完活立刻关 JMeter 不丢最后一份基线
- **WHEN** 回合刚终态、快照写盘任务仍在队列中，用户随即关闭 JMeter
- **THEN** 关闭流程有界等待该任务完成，快照落盘后才退出

#### Scenario: 冲刷超窗不阻断退出
- **WHEN** 关闭时快照任务超过等待上限仍未完成
- **THEN** 放弃该任务正常退出，MUST NOT 因快照卡死关闭流程

### Requirement: 快照内容纯净

写出的快照 SHALL 是可被 JMeter 正常打开的合法测试计划，且 MUST NOT 含插件注入的结果收集器节点（防插件内脏泄漏进快照）。剥离收集器 SHALL 只作用于克隆副本，MUST NOT 从活动 GUI 树上摘除节点（运行中的回合终态采样时活动树上可能存在收集器）。

#### Scenario: 运行中回合的快照不含收集器
- **WHEN** 回合终态采样时测试仍在运行（活动树含注入的收集器节点）
- **THEN** 落盘快照不含收集器节点
- **AND** 活动 GUI 树上的收集器节点未被快照流程摘除

### Requirement: 快照可发现性文档化且不新增工具

快照目录位置、命名规则、与 turnId 的对应关系及手动恢复方式（经既有打开 .jmx 工具）SHALL 写入 jmeter 技能文档供 agent 与用户查阅。本机制 SHALL NOT 新增枚举/恢复类工具（如快照列表工具）。

#### Scenario: agent 可依文档定位并恢复快照
- **WHEN** agent 需要把计划回退到某次回合之前
- **THEN** 其可依技能文档描述的目录与命名规则枚举快照、按 turnId 定位目标文件
- **AND** 经既有 open_jmx_file 工具打开该快照完成恢复，全程无需新工具
