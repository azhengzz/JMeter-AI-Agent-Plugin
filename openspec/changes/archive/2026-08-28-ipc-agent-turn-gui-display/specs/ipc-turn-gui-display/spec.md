## Purpose

让经 IPC `/agent` 到达的回合（其他实例委派与 `jmeter-cli` 直连）在目标实例的聊天面板中获得与本地回合对等的显示与控制：消息全流可见、按钮状态正确、可手动终止且终止有结构化反馈。

## ADDED Requirements

### Requirement: IPC 回合的完整对等显示

跑在当前实例会话上的 IPC 发起回合（`delegate_to_instance` 委派与 `jmeter-cli` 直连）SHALL 在目标实例聊天面板渲染与本地回合对等的完整消息流：来源消息（含来源前缀）、思考内容（遵循既有思考展示开关）、工具调用事件、进度提示、最终回复。IPC 回合的进度与渲染 MUST NOT 依赖"用户此前是否在面板发过消息"这类残留状态；面板已创建但处于隐藏状态时，消息流 SHALL 照常累积（重新可见时完整呈现）。

#### Scenario: 委派回合全流显示
- **WHEN** 实例 B 收到实例 A 的 `delegate_to_instance` 委派，B 的聊天面板已打开
- **THEN** 面板显示带 `[delegated-from …]` 前缀的来源消息
- **AND** 该回合的思考内容、工具调用事件、进度与最终助手回复均按本地回合相同的样式渲染

#### Scenario: CLI 直连回合全流显示
- **WHEN** `jmeter-cli agent "分析当前测试计划"` 到达目标实例且面板已打开
- **THEN** 面板显示带 CLI 来源前缀的该消息及其回合全流，直至最终回复

#### Scenario: 无残留依赖
- **WHEN** 目标实例本次启动后用户从未在面板发送过任何消息，随后收到委派回合
- **THEN** 该回合的消息流照常完整显示（不因缺少此前 GUI 发送而出现"只见工具事件不见消息"的半状态）

#### Scenario: 面板隐藏期间不丢失
- **WHEN** IPC 回合运行期间聊天面板处于隐藏（toggle 关闭）状态
- **THEN** 消息流照常累积，用户重新打开面板时可完整看到该回合内容

### Requirement: CLI 直连消息的来源前缀

`jmeter-cli` 直连（非委派）发送到 `/agent` 的**非命令**消息 SHALL 在进入会话前带上轻量来源前缀（`[from cli]`），前缀随消息文本持久化到会话存储（与 `[delegated-from …]` 前缀同为消息文本的一部分，构成单一事实源）。斜杠命令消息 SHALL NOT 加前缀并 SHALL 按既有命令分发生效（前缀会破坏命令的精确匹配分发）。委派消息 SHALL 保持既有 `[delegated-from …]` 前缀原样不变。

#### Scenario: CLI 消息带前缀入会话
- **WHEN** 用户执行 `jmeter-cli agent "运行测试"`
- **THEN** 目标实例会话中该 user 消息文本为 `[from cli] 运行测试`
- **AND** 面板按普通用户消息样式渲染该文本

#### Scenario: CLI 斜杠命令不加前缀照常分发
- **WHEN** 用户执行 `jmeter-cli agent "/status"`
- **THEN** 该消息不加来源前缀，按既有命令路径分发并返回状态快照
- **AND** 不作为普通消息进入会话上下文

#### Scenario: 委派前缀不受影响
- **WHEN** 对端实例委派任务到达
- **THEN** 消息文本保持既有 `[delegated-from instanceId=… pid=… script=…] <task>` 格式，不叠加 CLI 前缀

### Requirement: IPC 回合期间的按钮状态对等

当前实例会话上存在活跃回合时（无论发起方是本地用户、委派还是 CLI），聊天面板 SHALL 进入与本地回合一致的 Stop 模式：STOP 按钮可见可用，发送按钮表现为"注入"（将输入注入正在运行的回合）。回合结束（完成、失败、被取消）后 SHALL 恢复发送模式。

#### Scenario: 委派回合运行期间面板进入 Stop 模式
- **WHEN** 委派回合在目标实例上运行中
- **THEN** 面板 STOP 按钮可见可用，发送按钮表现为注入
- **AND** 不停留在"发送模式"导致用户无法终止

#### Scenario: IPC 回合结束后恢复发送模式
- **WHEN** 委派回合正常完成或被终止
- **THEN** 面板恢复发送模式（STOP 隐藏、发送按钮恢复发送语义）

### Requirement: 本地消息注入 IPC 回合

IPC 回合运行期间，本地用户在面板输入并发送的消息 SHALL 注入该回合（与本地回合的 mid-term injection 语义一致），回合的最终回复 SHALL 同时呈现于面板并回传给委派方/CLI。

#### Scenario: 注入委派回合并共享回复
- **WHEN** 委派回合运行中，目标实例用户在面板输入"顺便看下线程数"并发送
- **THEN** 该消息注入正在运行的委派回合
- **AND** 最终回复在面板显示，同时作为 `/agent` 响应回传给委派方

### Requirement: 手动终止 IPC 回合与结构化反馈

用户点击 STOP 终止 IPC 回合时 SHALL 立即执行（无确认弹窗，与本地 STOP 一致），且不得阻塞 UI 事件线程超过短暂时长（既有取消路径的秒级同步等待 SHALL 挪出事件线程）。委派方/CLI SHALL 收到结构化的终止反馈：明确的"被目标用户终止"状态与截至终止时已产生的助手部分内容，且该状态 MUST 与超时终止、其他取消途径可区分。`/agent` 响应体以新增可选字段承载（向后兼容，旧客户端可忽略）。被手动终止的回合维持既有"中止回合不落盘"语义。

#### Scenario: STOP 终止委派回合并回传部分内容
- **WHEN** 委派回合运行中，目标实例用户点击 STOP
- **THEN** 该回合被取消，UI 不出现秒级冻结
- **AND** 委派方收到含"被目标用户终止"原因与已产生部分内容的结构化响应

#### Scenario: 终止状态与超时可区分
- **WHEN** 委派方先后经历一次对端超时与一次被目标用户终止
- **THEN** 两次响应中的状态字段可区分这两种终止途径

#### Scenario: CLI 展示终止原因与部分内容
- **WHEN** CLI 发起的回合被目标实例用户终止
- **THEN** CLI 输出"被目标用户终止"原因及已产生的部分内容，而非笼统错误

#### Scenario: 委派工具结果区分终止原因
- **WHEN** `delegate_to_instance` 的对端回合被目标用户终止
- **THEN** 该工具返回给主代理的结果明确说明"被目标实例用户终止"（区别于对端超时或执行失败）

#### Scenario: 被终止回合不落盘
- **WHEN** IPC 回合被手动终止
- **THEN** 该回合的消息不写入会话存储（维持中止回合跳过落盘的既有语义）

#### Scenario: STOP 后新输入不注入垂死回合
- **WHEN** 用户点击 STOP 终止回合后立即发送新消息
- **THEN** 该消息作为新回合正常发送（取消时注入路由同步摘除）
- **AND** 不会被注入垂死回合而遭取消契约静默作废

### Requirement: 回合生命周期系统提示

以下生命周期事件 SHALL 在目标实例面板各显示一行系统提示：对端等待超时导致回合被取消（超时自取消）、委派请求因会话忙被快速拒绝、用户手动终止 IPC 回合（含"部分结果已回传"回执）。提示 MUST NOT 与会话消息混淆（以系统提示样式呈现，不写入会话存储）。

#### Scenario: 超时自取消提示
- **WHEN** 委派方等待超时，目标实例按既有超时机制取消该回合
- **THEN** 面板出现一行说明该回合因对端超时被终止的系统提示

#### Scenario: 忙拒绝提示
- **WHEN** 委派请求到达时当前会话已有活跃回合，请求被既有 session busy 机制快速拒绝
- **THEN** 面板出现一行说明有委派被拒收的系统提示，委派方收到既有 busy 错误

#### Scenario: 手动终止回执提示
- **WHEN** 用户 STOP 终止 IPC 回合
- **THEN** 面板出现一行说明该回合已终止、部分结果已回传给发起方的系统提示

### Requirement: 显示范围与 headless 边界

面板显示 SHALL 仅覆盖跑在当前实例会话上的 IPC 回合：显式指定其他会话键的 `/agent` 请求（如 `jmeter-cli --session foo`）SHALL 保持 headless 执行，不进面板。本次 JMeter 启动以来聊天面板从未被创建时，IPC 回合 SHALL 保持 headless（不自动创建/弹出面板，不缓冲补放）；面板一经创建后到达的 IPC 回合按上文要求显示。会话持久化行为不变：正常完成的 IPC 回合写入会话存储，中止回合跳过。

#### Scenario: 指定其他会话键的请求不进面板
- **WHEN** `jmeter-cli agent --session foo "独立任务"` 到达且面板已打开
- **THEN** 该回合在会话 `foo` 上 headless 执行，面板不显示其消息流

#### Scenario: 面板未创建时保持 headless
- **WHEN** JMeter 启动后用户从未打开聊天面板，此时委派请求到达
- **THEN** 回合照常执行并按既有规则持久化，面板不被自动创建，无任何 UI 弹出

#### Scenario: 正常完成回合照常落盘
- **WHEN** IPC 回合正常完成
- **THEN** 其消息按既有规则写入当前实例会话存储
