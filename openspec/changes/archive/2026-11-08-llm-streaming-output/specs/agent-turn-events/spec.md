# Spec Delta

## MODIFIED Requirements

### Requirement: 事件顺序保证

同一回合内 SHALL 保持 开始 → 进度* → 恰好一个终态 的全序；跨回合 SHALL 保持 回合 N 的终态先于回合 N+1 的开始（自然完成路径）；垂死回合的终态 SHALL 先于其收尾 re-publish 的孤儿回合开始事件。发射 SHALL 同步内联于发射线程（无中间队列），订阅者单入口恰一次编组到目标线程后按先进先出交付。取消路径例外：取消终态在任务槽摘除之后才发射，槽已空窗口内新回合可开跑——取消终态(N) SHALL 允许晚于新回合开始(N+1) 到达，订阅者 MUST 按回合身份过滤而非依赖跨回合到达顺序。流式扩展：每次 LLM 调用的流段事件（开始 → 增量* → 流段结束，挂 PROGRESS 载荷）SHALL 构成进度序列内的有序子序列，且某次调用的流段结束事件 SHALL 严格先于该调用触发的工具进度与回合终态；provider SHALL 在返回前收完整条流，使流段子序列与后续进度/终态的顺序由构造保证。

#### Scenario: 跨回合终态先于下回合开始

- **WHEN** 回合 N 终止（完成/取消）后新回合 N+1 开始
- **THEN** 订阅者先收到回合 N 的终态事件，后收到回合 N+1 的开始事件

#### Scenario: 取消路径倒序容忍

- **WHEN** 取消信号摘除回合 N 的任务槽后、取消终态发射前，新回合 N+1 已开跑并发射开始事件
- **THEN** 订阅者可能先收到 N+1 的开始、后收到 N 的取消终态，两者均照常处理（按回合身份过滤，互不吞没）

#### Scenario: 孤儿开始严格晚于垂死回合终态

- **WHEN** 垂死回合在收尾时 re-publish 出孤儿回合
- **THEN** 订阅者先收到垂死回合的终态，后收到孤儿回合的开始事件

#### Scenario: 流段结束先于工具进度与终态

- **WHEN** 一次 LLM 调用流式产出正文后发起工具调用，工具执行完回合进入终态
- **THEN** 订阅者收到的顺序为：该调用的流段开始 → 增量* → 流段结束 → 工具进度 → （后续调用流段或）回合终态
